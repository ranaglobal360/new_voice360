User flow map — Automatic Voice 360 Pages
Eleven screens, one page per organisation. Pages are generated automatically on approval — never created by hand — and no organisation has more than one, no matter how many modules it appears in. Tabs are dynamic: a cafe shows Products, a professional shows Services, a travel provider shows Packages.

Flow A
The public page
3 screens · what a visitor or follower sees
PG01
Page Home
Logo, verification mark, cover, category, address, rating, followers, opening status · one dedicated action · dynamic tiles

PG03 · TAB
About & Information
Description, map with service area, three contact rows, opening hours with live status, and the verification block naming every module this page serves
Flow B
What the page sells

PG04 · ONE DYNAMIC DESIGN
Products, Services & Packages
Category rail, search, live result count, in-stock toggle, price sort. The same screen serves every page type
PG05 · TAB

Current, saved and expired in one list. Expired offers stay visible but dimmed and unactionable
PG06 · TAB

Flow C
Media & audience
2 screens · the last two public tabs
PG07 · TAB

Flow D
Owner side
3 screens · visible to the owner and authorised staff only
PG09 · OWNER & STAFF
Page Owner Dashboard
Page status first, six metrics, five quick actions, then the two things needing attention — the verification alert and profile completion
PG10 · OWNER & STAFF
Edit Page Information
Every field editable, with two constraints made visible: the address changes only through the unified location picker, and verified fields go to review before publishing
PG11 · 3 TABS, ONE SCREEN
Roles, Settings & Insights
Roles shown in full with the four staff levels and permission changes; Settings and Insights summarised with their complete option and metric sets
The rule
One page per organisation, generated automatically on approval. Never created by hand, never duplicated across modules — every listing points at the same page.
Future phase
Marked on the board as not part of the current Parliamentary flow. Designed and codified here so it is ready when the phase is confirmed.
Depends on
The admin verification queue creates pages and reviews owner edits. Messages carries Message-to-order. Neither is built for this flow yet.
